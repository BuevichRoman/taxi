# Мок API перерывов

Реализация контракта из [`docs/ТЗ-001-контракт-API-перерывов.md`](../docs/ТЗ-001-контракт-API-перерывов.md).

Нужен для двух вещей:

1. разрабатывать клиентскую часть, не дожидаясь готовности backend;
2. прогонять сценарии приёмки из раздела 15.2 ТЗ, не завися от тестового
   стенда и не ожидая реального времени.

Заодно служит исполняемой спецификацией: тесты в `src/execution.test.ts`
показывают, какого поведения клиенты ждут от боевого сервера.

## Запуск

```bash
npm install
npm start
```

Слушает `http://localhost:4010` (порт меняется переменной `PORT`).

```bash
npm test        # сценарии приёмки, 35 проверок
npm run typecheck
```

Сборка не нужна: Node запускает TypeScript напрямую. Требуется Node 22.6+.

## Маршруты

| Маршрут | Назначение |
|---|---|
| `POST /drive` | создать заказ |
| `POST /drive/get/:id` | действие над заказом, `action` в теле |
| `GET /drive/get/:id` | прочитать заказ (этим пользуется опрос из бота) |

Поддерживаемые значения `action`: `set_start_state`,
`set_break_start_state`, `set_break_end_state`, `set_complete_state`.
Тело принимается в трёх видах: `multipart/form-data` (как шлёт SPA),
`x-www-form-urlencoded` и JSON.

### Служебные маршруты

Их в боевом API нет, они существуют только для прогона сценариев.

| Маршрут | Назначение |
|---|---|
| `POST /_test/advance` | сдвинуть часы вперёд: `{"seconds": 3600}` |
| `POST /_test/reset` | очистить заказы и вернуть часы |
| `GET /_test/orders` | показать все заказы |

Сдвиг часов — ключевая вещь для приёмки: шестичасовой заказ с тремя
перерывами прогоняется за пару секунд, а метки времени остаются
согласованными.

## Пример

```bash
# заказ на 6 часов с часовым плановым перерывом
curl -X POST localhost:4010/drive \
  -F "b_start_datetime=2026-07-28T09:00:00.000Z" \
  -F "b_end_datetime=2026-07-28T15:00:00.000Z" \
  -F 'planned_breaks=[{"started":"2026-07-28T11:00:00.000Z","ended":"2026-07-28T12:00:00.000Z"}]' \
  -F "performer_u_id=nanny-1"

curl -X POST localhost:4010/drive/get/1 -F "action=set_start_state" -F "u_id=nanny-1"
curl -X POST localhost:4010/_test/advance -H 'Content-Type: application/json' -d '{"seconds":2400}'
curl -X POST localhost:4010/drive/get/1 -F "action=set_break_start_state" -F "u_id=nanny-1"
curl -X POST localhost:4010/_test/advance -H 'Content-Type: application/json' -d '{"seconds":10800}'
curl -X POST localhost:4010/drive/get/1 -F "action=set_break_end_state" -F "u_id=nanny-1"
```

## Что эмулируется, а что нет

**Эмулируется:** машина состояний перерывов и все ограничения раздела 14 ТЗ,
агрегаты времени, округление, флаг `display` для коротких перерывов, расчёт
стоимости по боевой формуле, серверное время в каждом ответе, коды ошибок из
раздела 5 контракта, автозакрытие перерыва при завершении заказа (ТЗ п. 17).

**Не эмулируется:** авторизация (`token` / `u_hash` игнорируются), поиск
исполнителя, платежи, чат, справочники и всё остальное API заказа. Хранилище
в памяти — состояние теряется при перезапуске.

## Расхождения с боевым API, требующие сверки

Это открытые вопросы из раздела 7 контракта. Мок сделан по нашему
предположению; когда backend ответит, поправим здесь.

1. **Формат времени.** Мок отдаёт ISO 8601 в UTC (`...Z`), в контракте пример
   со смещением `+03:00`. Оба варианта корректны, но формат должен быть один.
2. **Округление.** Взято предложенное правило — вверх до минуты
   (`ROUNDING` в `src/config.ts`). В боевой системе правила нет вообще, его
   предстоит завести (см. раздел 3.3 контракта).
3. **`MIN_VISIBLE_BREAK_DURATION`** = 60 секунд. Значение выбирает backend.
4. **Код ошибки `invalid_state`** в контракт не входит. Используется только
   там, где мок обслуживает действия вне нашей задачи — например, повторный
   `set_start_state` или обращение к несуществующему заказу. Поведение
   боевого API в этих случаях определяется существующей реализацией.
5. **HTTP-код при ошибке** — всегда 200, ошибка передаётся в теле, как в
   существующем API (клиент проверяет `response.data.status === 'error'`).

## Константы расчёта

Взяты из боевой конфигурации тенанта `children`
(`site_constants.pricingModels`, модель `basic`):

```
(base_price + distance * price_per_km + duration * price_per_minute)
    * time_ratio * car_class_ratio + options_sum + submit_price
```

`base_price = 200`, `price_per_km = 10`, `price_per_minute = 5`,
`time_ratio` = 1 днём и 0.5 ночью, `car_class_ratio` = 1 / 1.5 / 2.

`duration` подставляется **в минутах** — это и есть единственная точка, где
перерывы влияют на стоимость. Результат обрезается вниз до целого, как это
делает `Math.trunc` в `calculatePrice()` бота.
